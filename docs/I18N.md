# Checkout localization

The checkout uses Vue I18n's Composition API. English remains the default and the only shipped translation. The app installs a fresh instance from `src/i18n/index.ts`; components use `useI18n({ useScope: "global" })`.

## Message resources

- `src/i18n/locales/en.ts`: shared checkout, selection, transfer, receipt, retry and error messages.
- `src/i18n/locales/en-secondary.ts`: demo tools, invalid-link, merchant fallback and explorer accessibility messages, composed into the English catalogue.
- `MessageSchema` and Vue I18n's `DefineLocaleMessage` describe the source catalogue for editor/type support.

Use stable descriptive keys and named interpolation parameters. Keep a complete sentence in a message rather than joining translated sentence fragments. Use `i18n-t` with named slots for styled amounts, the countdown and other embedded elements; translators can reorder the placeholders without changing the DOM structure. Never use `v-html` to render translations or API values.

## Add another language

1. Add `src/i18n/locales/ko.ts` (or another locale), exporting the same nested message shape. `import type { MessageSchema } from ".."` and `satisfies MessageSchema` can enforce completeness without a runtime import.
2. Import that resource in `src/i18n/index.ts` and register it in `messages`, for example `{ en, ko }`.
3. Open `/?lang=ko`. Regional requests such as `ko-KR` resolve to `ko` when only `ko` is registered. Unsupported values fall back to English. Missing translations also fall back to English through Vue I18n.
4. If a language picker is added later, change the global Composer's `locale.value` to a registered locale. Existing messages, including copy feedback, update reactively. This must not create, replace or reload a payment.
5. Review wording, accessible labels, long text at mobile widths, plural forms and all payment states. Verify the existing English UI and payment behavior remain unchanged.

No language picker or locale persistence is introduced. `App.vue` synchronizes the document's `lang` attribute with the active UI language. The neutral loading title is translated; a verified merchant name still takes precedence.

## Payment values and formatting

The existing `?locale=de-DE` parameter controls fiat formatting, independently of `?lang=`. Existing timestamp formatting remains `en-GB`. These formatting policies are unchanged by this extraction.

Amounts remain exact decimal strings and use the existing BigInt/string money helpers. Do not pass transfer amounts through `Number`, `parseFloat`, or Vue I18n's numeric formatter. Never translate or alter QR payloads, clipboard transfer values, references, currency codes, API merchant/network names, transaction hashes, or request/status enums.

The controller and HTTP client retain their existing English diagnostic strings for injected-client compatibility. `src/i18n/paymentErrors.ts` maps only known application messages to translation keys at the presentation boundary. Unknown backend error text/reason codes remain data and are not interpreted as message keys or HTML. Demo status options retain the API codes.
