## Findings and resolutions

**Major, R03/T03:** new replacement response reference was rejected because the controller's default expected reference still selected the previous payment, despite replacement mode. Reproduction is `tests/component/controller.test.ts` “ignores an old response delivered during serialized replacement.” Implementer corrected the default-reference rule; independent controller and browser replacement tests now pass. This was a real rejected implementation behavior and must remain in the work history.

Test-interface corrections preserved source expectations: Vue can join adjacent text nodes without a literal space, so the exact outstanding-number/unit assertion allows whitespace; a disabled Continue during replacement is not a usable send action, while detected explicitly prohibits every Continue/send action; a detection race fixture must preserve the original quote expiry or boundary validation correctly rejects it; HTTP 500 wording is asserted by the fault itself rather than arbitrary synonyms; clicking a replacement radio avoids Playwright checking a node that correctly disappears immediately afterward.
