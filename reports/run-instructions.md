# Running the checkout

Use Node 22.12 or newer (verified on 22.19.0), npm 10.9.3. Run `npm ci`, then `npm run dev`. The script starts Vite at http://127.0.0.1:5173 and the HTTP mock at http://127.0.0.1:8787; Vite proxies `/api`. Stop with Ctrl-C. Do not run dev and preview together on the default mock port.

For the built application: `npm run build`, then `npm run preview`. Preview serves http://127.0.0.1:4173 and starts the same mock. Set MOCK_PORT to another local port when concurrent isolated verification requires it. The browser stores only the payment reference and restores the screen from a fresh API response when reopened. The mock still keeps payments only in memory: restarting it or resetting the demo removes them; an unknown saved reference is cleared and checkout starts fresh. Reset demo also clears this tab’s order reference. References are stored separately under `stablecoin-checkout:payment-reference:<ORDER_ID>`; a missing payment clears only its order’s key. The demo sends no real funds.

Open http://127.0.0.1:5173/?demo=1 to show evaluator controls below the shopper page. Add `?order=ORD-88214` (or `?order=ORD-88214&demo=1`) to open another order. Omitting `order` uses `ORD-88213`; a present value must match `ORD-` followed by exactly five digits, otherwise the page shows an invalid-link message without making API calls. Each order restores independently across tabs and reopenings in the same browser storage. Opening the same order again restores its saved payment. Continue creates a quote. Expand Demo controls and set Order amount (EUR), then Apply amount: before any payment exists, Total to pay updates immediately. The amount applies only to the next created or requoted payment; an existing payment keeps its original amount. Use Change, select a network, and Continue to create a replacement, or Get a new quote after expiry. Reset demo restores EUR 149.90. Choose a Payment state and Apply state; all eight API states are supported and each command targets this page’s order. Order amount controls also apply only to this order. Connection controls choose Healthy, HTTP 500, Disconnect or Slow (5 seconds), then Apply connection. Advance 15 minutes advances the mock clock: awaiting quotes can expire, while detected/confirming payments gain one confirmation per selected network’s avg_confirmation_seconds until paid; ordinary waiting also progresses confirmations unless the mock clock is frozen. Reset demo is global: it removes every order’s payments and funds locks and resets amounts, clock, metrics, and reference sequence. Other tabs discover missing payments on their next refresh or reload; terminal receipts need a reload. Reset before exploring a different terminal lifecycle. These controls intentionally bypass provider-like progression and are a local evaluation surface only.

Transaction hashes display as shortened links with an external-link icon. Hover to read the full hash. Ethereum opens Etherscan, Polygon opens PolygonScan, Tron opens TRONSCAN, and Solana opens Solscan in a new tab. The mock supplies full synthetic identifiers (not real on-chain payments), so explorer pages may report that the transaction was not found. Restart `npm run dev` after mock-code changes, then Reset demo to load the updated fixtures. Incomplete legacy hashes remain plain text because their missing characters cannot be recovered.

HTTP controls: POST `/api/demo/reset` with `{}` resets state; optional `now` (ISO), `freeze` (boolean) and `ttlMs` produce deterministic scenarios. Both reset and scenario accept `orderAmount`, a decimal string from "0.01" to "999999.99" with at most two decimal places, normalized to two decimals; invalid amounts return HTTP 400 with title "Invalid order amount" and leave state unchanged. Reset without `orderAmount` restores "149.90" for every order; a reset amount override configures only the default order, `ORD-88213`. POST `/api/demo/scenario` with `status`, `fault` (`none`, `500`, `disconnect`, `slow`), `delayMs`, `advanceMs`, or `orderAmount` controls the server. Scenario commands accept `order_id` (default `ORD-88213`) for payment status and order amount; faults, delays and time advances remain global. Order amount changes apply to that order’s next create/requote; current payments remain fixed. Quotes scale the literal demo principal proportionally to EUR 149.90 using integer arithmetic, rounded half up at the token scale, then add the unchanged network fee. GET `/api/currencies?order_id=ORD-88214` includes that order’s amount and merchant metadata as well as the unchanged currency catalogue; the plain URL defaults to `ORD-88213`. GET `/api/demo?order_id=ORD-88214` exposes that order’s scenario and payment, global request metrics and mock time, plus an `orders` array of `{order_id, payment_reference, status, fundsObserved}` for all known orders. The plain demo URL also defaults to `ORD-88213`. Orders are created lazily by the first quote; catalogue reads and pre-quote amount configuration do not create orders. References remain globally unique until reset. Replacement invalidates only the same order’s unfunded attempt; observed funds block further creates/requotes for that order even after a later failed state. There is no order-creation API, shopper authentication, or payment list page. Controls bypass injected faults. Normal quotes last 15 minutes. For the requested quick browser expiry check, reset with `{ "ttlMs": 15000 }`; the committed real HTTP browser case verifies expiry and same-reference recovery after 15 seconds. Server responses include ISO `x-server-time` and `Cache-Control: no-store`.

Use `?locale=en-IE` or `?locale=de-DE` to inspect fiat formatting while retaining English UI. No real wallet, account, blockchain, provider affiliation, merchant contact URL or return destination is configured.

Checks: `npm run typecheck`, `npm run lint`, `npm run build`, `npm run test:unit`, `npm run test:component`, `npm run test:contract`, `npm run test:e2e`, and `npm run test:visual`. `npm run verify` aggregates ordinary checks; independent review and mutation evidence live in reports/gates. Browser setup: `npx playwright install chromium`. The browser suite opens an isolated headed Chromium window for the required two-minute background-tab observation; leave that test window alone until it closes. The separate expiry case uses 15 seconds.

For a formal isolated mutation audit, use `npm run test:mutation -- --candidate <reviewed-commit-sha> --g4-evidence reports/gates/G4.md`. It requires the exact Git candidate and recorded G4 clearance. `npm run test:mutation -- --candidate <commit-sha> --preflight` is development readiness only. Each defect is injected into an isolated archived copy and restored. Inspect the detailed result, including any surviving equivalent change, rather than treating an exit code alone as test-effectiveness approval.

Formal verification is separate from developer checks. README creation remains deferred by request.
